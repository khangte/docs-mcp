시스템 아키텍처

두 진입점(MCP 서버 · 배치 스케줄러)이 하나의 서비스 계층을 공유하고, 검색은 항상 키워드(FTS)와 벡터(HNSW) 신호를 RRF로 융합한다.

주목할 설계 결정 3가지

01

미색인 문서도 죽지 않는 검색

협업 문서 검색은 제목 arm의 키를 deterministic_document_id()로 순수 계산해, 본문이 아직 색인 안 된 문서도 제목 신호만으로 결과에 남는다 — 별도 폴백 분기 없이.

02

멀티 프로젝트, 격리는 태그로

하나의 프로세스·DB가 여러 프로젝트를 함께 서비스한다. Drive/Notion 자격증명은 전역 공유, 프로젝트마다 달라지는 건 폴더/DB 매핑뿐이라 신규 프로젝트 온보딩 비용이 낮다.

03

advisory lock으로 만든 안전한 배치

메타 동기화·재색인·본문 색인 세 축을 다른 주기로 돌리면서도, 새 의존성 없이 Postgres advisory lock만으로 중복 실행과 서로의 기아 상태를 막는다.

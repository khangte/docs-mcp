# "지금 무조건 N:1로 바꾸자" vs 게이트형 조건부 sub-chunking — 재검토 판단

- 상태: **판단 only** — 코드 미수정.
- 일시: 2026-08-13
- 작성: architect
- 질문(사용자): parent-child는 원래 N:1이어야 했는데 지금 1:1이고 doc/23이 그걸 보수하는 거라면, 게이트(실사례 트리거 대기, Phase0 측정 0건) 없이 `chunk_builder`를 지금 바로 **무조건 N:1 분할**(모든 섹션을 작은 sub-chunk 여러 개로)로 바꾸는 게 낫지 않나?
- 참고: `docs/architect-review/23`(sub-chunking 설계), `24`(parent-child 비교), `16`(맹점·Phase0/1), `13`(문맥청킹 픽스처 아티팩트 교훈), `09·15`(재색인 게이트)

---

## 0. 결론 먼저

**게이트형(doc/23 gate-B: 조건부 splitter 병합 + 실배선은 실사례 대기)이 무조건 N:1 전환보다 낫다.** 사용자 전제 두 개를 정정한다:

1. **"1:1은 미완성 parent-child고 N:1이 정답"이 아니다.** 이 프로젝트의 parent(헤딩 섹션)는 **그 자체가 의미 응집 단위**다. 섹션이 임베딩 예산(480토큰) 안에 들면 child=parent(1:1)가 **최적** — 임베딩 단위에 문맥을 최대로 담고, 파편화·dedupe 오버헤드가 없다. parent-child(N:1)는 **parent가 예산을 넘을 때만** 이득이 생긴다. 즉 doc/23의 "넘으면 쪼개고 아니면 1:1"은 미완성 보수가 아니라 **정확히 옳은 조건 분기**다.
2. **무조건 N:1은 "더 올바른 parent-child"가 아니라 패턴 과적용이다.** 표준 RAG가 작은 고정 윈도우를 쓰는 건 자연스러운 응집 단위가 **없어서**다. 여기엔 헤딩 섹션이라는 응집 단위가 이미 있으니, 짧은 섹션까지 문단으로 쪼개는 건 이점 없이 해만 남긴다(§2).

## 1. 무조건 N:1 전환의 비용 (지금 바로 바꿀 때)

| 비용 축 | 내용 | 크기 |
|---|---|---|
| **즉시 전면 재색인** | 모든 문서의 섹션 청크를 재분할·재임베딩. 로컬 CPU SentenceTransformer 인코딩이 병목(docs/09 게이트 근거) | **큼**. 게이트가 막으려던 바로 그 비용을 자발적으로 지불 |
| **청크 폭증 = 인덱스 비대** | 섹션 수 → 문단 수로 행 급증. 각 child = text + 384-dim 벡터 + tsv + **HNSW 엔트리**. HNSW 빌드/질의 비용↑ | **중~큼**. 게다가 아래 이유로 **이득 0** |
| **이득 미실현 (결정적)** | 섹션 child는 **현재 벡터 검색 경로에 안 탄다** — `search_by_vector`가 `chunk_type=="endpoint"`로 하드 제한(doc/24 C표 4행). 작은 child의 정밀도 이점은 **배선 전엔 실현 불가**. 비용 전액 지불 + 검색 이득 0 | **치명** |
| **짧은 섹션 문맥 파편화 (새 리스크)** | 맹점(512 초과)의 **반대 방향** 해악. 100토큰 섹션을 문단 3개 child로 쪼개면 각 child가 섹션의 문단 간 문맥을 잃고 **개별 임베딩 품질이 되레 저하**. 코퍼스 대부분이 짧은 섹션(doc/16 실측 endpoint/schema avg 40토큰)이라 **손해가 지배적** | **중**. 무조건 분할에만 있는 순손실 |

요약: 무조건 N:1은 **막대한 재색인 + 인덱스 비대**를 지불하고, 그 대가로 **① 배선이 안 돼 검색 이득 0, ② 짧은 섹션은 되레 recall 저하**를 얻는다. docs/13 교훈(문맥청킹을 이론만으로 넣었다 픽스처 아티팩트로 소멸)의 재연 위험.

## 2. 게이트형(doc/23 gate-B)의 비용

| 비용 축 | 내용 | 크기 |
|---|---|---|
| **대응 지연** | 새 데이터에 512 초과 섹션이 나타나면 그 섹션의 512 이후 내용이 벡터 arm 발견성에서 누락 — 실배선 전까지 | **작음·한정**: ① Phase1 경고 로깅이 이미 배선돼 **조용하지 않다**(로그가 뜸), ② 손실은 벡터 arm 발견성 한 갈래뿐, 키워드 arm·저장 본문·반환은 온전(doc/16 §1-4), ③ 측정상 현재 0건 |
| **휴면 코드 유지** | 조건부 splitter가 병합돼 있으나 `count_tokens=None`이라 기존 경로 무영향 | **거의 0** |

## 3. 정면 비교

| | 무조건 N:1 지금 전환 | 게이트형(gate-B) |
|---|---|---|
| 재색인 | **즉시 전면**(회피 가능했던 비용) | 실사례 시에만 |
| 인덱스 비대 | 즉시·영구, 이득 0(미배선) | 없음 |
| 짧은 섹션 | **파편화로 recall 저하** | 1:1 유지 = 최적 |
| 512 초과 섹션 대응 | 해결하나 미배선이라 검색 반영 안 됨 | 로깅으로 가시화 + 트리거 시 배선 |
| docs/13·15 원칙 | **위배**(측정 없이 큰 변경) | 준수 |
| 되돌리기 | 재색인 필요 | 배선 한 줄 on/off |

무조건 N:1은 **모든 칸에서 지거나 비긴다.** 유일한 명목 이점("512 초과 즉시 분할")조차 미배선이라 검색에 반영되지 않는다.

## 4. 판단

- **채택: 게이트형(doc/23 gate-B) 유지.** 무조건 N:1 전환 반려.
- **근거 한 줄**: 분할은 "예산 초과 시"라는 조건이 붙을 때만 옳다. 무조건 분할은 대다수인 짧은 섹션을 파편화해 recall을 깎고, 정밀도 이득은 섹션 벡터 미배선으로 실현되지도 않으며, 회피 가능한 전면 재색인을 자발적으로 문다.
- **사용자 전제 정정**: "1:1 = 미완성"이 아니다. 응집 단위(헤딩 섹션)가 예산에 맞으면 1:1이 정답이고, doc/23의 조건 분기(넘으면 N:1, 아니면 1:1)가 완성형이다.
- **만약 진짜로 "작은 child의 검색 정밀도"를 원한다면** 그건 별개 트랙: 먼저 (a) 섹션을 벡터 검색에 배선하고 (b) 작은 child가 섹션 recall을 **실측으로** 올리는지 확인해야 한다(docs/13 교훈). 그 측정 없이 무조건 분할부터 켜는 건 순서가 뒤집힌 것.
- **다음 행동 없음**(판단만). doc/23 gate-B가 그대로 유효. 실배선·재색인은 Phase0 재측정이 512 초과 실사례를 보일 때 트리거.

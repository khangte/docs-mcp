# 77. C2~C4 진단 드리프트 대역과 귀속 한계 판정

- 대상: `docs/eval-results/05_2026-08-28_keyword_variant_p02_eval.md` §2 postrevert 재측정
- 상태: **문서 승인. 단 §3.2 q04 결론 표현 1건 수정 요구**

## 1. 드리프트 대역이 측정됐다

postrevert 검색 코드는 doc 03 baseline `429302c`와 byte-identical이다
(`git diff 429302c HEAD -- app/services/search/` 비어 있음). 그런데 같은 코드의 두 run이
다음만큼 다르다.

| 질의 | doc03 | postrevert | 이동 |
|---|---|---|---|
| q06 | 3 / 3 | 5 / 11 | top10 rank +2, **OK 경계(≤3) 이탈** |
| q05 | 미 / 41 | 미 / 44 | top50 +3 |
| q07 | 미 / 22 | 미 / 24 | top50 +2 |

원인은 developer가 적은 대로 run마다 임시 DB를 새로 색인하는 데서 오는 재색인·
e5-small 비결정성이다(verdict 70). 코드 회귀가 아니다.

중요한 것은 이 관측이 **`diagnose_variants.py` 결과의 해상도 하한을 정한다**는 점이다.
top10 rank 2계단, top50 3계단 이내의 이동은 코드 효과와 구분되지 않는다. 분류 라벨조차
경계에서 뒤집힌다.

## 2. q04 결론은 대역 안에 있다

§3.2는 q04(`POST /v1/customers` on top10 1 → 3 → revert 후 1)를 두고 "이 악화가 B의
비용이었음이 확인된다"고 쓴다. **확정할 수 없다.** 이동 폭 2계단은 위 표의 q06
드리프트(2계단, 그것도 분류를 바꾼)와 같은 대역이고, 세 수치 모두 공유 인덱스가 아닌
별도 run에서 나왔다. 왕복 복귀는 시사적이지만 단독 실행으로는 증거가 되지 않는다.

같은 기준에서 q05·q07 귀속은 **유지한다**. q05는 top50 41 → top10 3위(미검출 →
OK 승격), q07은 top50 22 → top10 6위다. 대역 밖이고 방향도 일관된다.

수정 요구: q04 항목을 "B의 비용으로 확정"이 아니라 "드리프트 대역과 같은 크기여서
단독 실행으로는 B 비용으로 확정할 수 없다. 확정하려면 공유 인덱스 짝 실행이 필요하다"로
바꾼다. §3.2 결론(B는 순개선이 아니었다)은 p02 게이트 FAIL이라는 별도 증거로 이미
성립하므로 바뀌지 않는다.

## 3. 이후 진단 실행 규칙

`diagnose_variants.py`의 run별 임시 DB 방식은 탐색용으로는 유지한다. 다만 순위
이동을 코드 효과로 귀속하려는 목적에는 쓰지 않는다. 그런 비교는 이미 있는
`run_corpus_eval.py --mode preflight/eval` 공유 물리 인덱스 짝 실행으로 한다
(verdict 70 §4.3/§4.4, 이 문서 §1의 p02 게이트가 쓴 방식). 새 도구를 만들지 않는다.
